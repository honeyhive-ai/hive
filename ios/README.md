# Hive for iPhone

A personal, single-user SwiftUI client for a Hive home host (`hive serve`).
The phone is a thin client: it talks plain HTTP + Server-Sent Events to the
home host over Tailscale with a bearer token. E2EE keys, relay sync and the
agent worker all stay on the home host.

- iOS 26.0+, Swift 6 (strict concurrency), no third-party dependencies
- Bundle id `com.zazulam.hive.lab`, URL scheme `hive`

## Project

The Xcode project is generated by [xcodegen](https://github.com/yonaskolb/XcodeGen)
from `project.yml`. `Hive.xcodeproj` is **gitignored**; regenerate it after
pulling or after adding/removing files:

```sh
cd ios
cp Config/Local.xcconfig.example Config/Local.xcconfig   # once; set DEVELOPMENT_TEAM
xcodegen generate
open Hive.xcodeproj
```

The signing team is personal, so it lives in the untracked
`Config/Local.xcconfig` (the OU of your "Apple Development" certificate:
`security find-certificate -c "Apple Development" -p | openssl x509 -noout -subject`).
Signing is automatic.

## Build and test

```sh
# unit tests (Swift Testing) on a simulator
xcodebuild -project Hive.xcodeproj -scheme Hive \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test

# device build (automatic signing)
xcodebuild -project Hive.xcodeproj -scheme Hive \
  -destination 'generic/platform=iOS' -allowProvisioningUpdates build
```

## Pairing

On the home host run `hive serve --pair`; it prints a QR code for
`hive://pair?url=<base64url(serverURL)>&token=<token>`. Scan it in the app,
paste the link, open it from another app, or enter the URL and token by hand.
The app checks `GET /v1/health` and one authorized call before saving the
server URL and token to the Keychain (this device only).

`hive://chat/<id>` opens a chat; ntfy notifications use it as their `Click` URL.

## Mock mode

Launch with `-mockServer` to run against an in-process fake server (a
`URLProtocol`, so the real API and SSE clients are exercised). Extra launch
arguments drive the UI for screenshots:

| Argument | Effect |
| --- | --- |
| `-mockStreaming` | stream a fake agent reply into the first chat on connect |
| `-showPairing` | start on the pairing screen |
| `-tab chats\|agents\|review\|lab\|settings` | select a tab |
| `-openChat <id>` | open a chat (fixture `c-lab`) |
| `-openProposal <id>` | open a proposal (fixture `p1`) |

```sh
xcrun simctl launch booted com.zazulam.hive.lab -mockServer -mockStreaming -openChat c-lab
```

## App Transport Security

The home host serves plain HTTP on a Tailscale `100.x.y.z` address (or a
MagicDNS name). ATS exception domains match host names, not IP ranges, so
there is no narrow exception for "any 100.64.0.0/10 address". The app
therefore sets only `NSAllowsArbitraryLoads`, which is acceptable for a
personal, non-App-Store app whose traffic is confined to the tailnet (WireGuard
already encrypts it).

Do **not** add `NSAllowsLocalNetworking` alongside it: when both keys are
present, the local-networking key takes precedence and arbitrary HTTP loads
are blocked again.

## Layout

```
Hive/App          app entry, AppModel (state + event folding), deep links
Hive/Networking   models, actor APIClient, SSE parser, EventStream, Keychain
Hive/Mock         in-process mock server + fixtures
Hive/Views        Pairing, Chats, Chat, Agents, Review (diff viewer), Lab, Settings
HiveTests         Swift Testing suites (URLProtocol stubs, SSE, deep links, Keychain, mock e2e)
```
